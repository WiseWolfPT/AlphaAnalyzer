QUESTIONS & ANSWERS
================================================================================

Q: Why weren't IV methods invalidated originally?
A: Earnings monitor was designed to only refresh analyst estimates cache.
   IV method cache service was created later but never integrated into
   earnings event flow.

Q: Will this slow down earnings processing?
A: Minimal impact (~50-100ms per event). Invalidation is fast Redis DEL.
   No additional FMP API calls (they still happen in warmCache).

Q: What if analyst estimates don't change for a stock?
A: IV methods still invalidated (conservative approach). Unnecessary
   recalculation is faster than stale data. WarmMethod() handles caching.

Q: Should DDM and Graham Number be in affected methods?
A: YES - both depend on analyst growth estimates. Added to fix.
   REVIEW: May also want 'p-tbv-mean', 'p-tbv-sector', 'ffo-reit',
   'affo-reit', 'p-ffo-mean', 'p-ffo-sector', 'dividend-yield-reit'
   if they use analyst data (unclear from code).

Q: How many IV methods per stock?
A: 12 methods currently supported (FCFE methods removed)

Q: Will this increase FMP API usage?
A: No. Methods invalidated but not recalculated until user request (lazy).
   No automatic warming of IV methods (only analyst estimates warmed).
