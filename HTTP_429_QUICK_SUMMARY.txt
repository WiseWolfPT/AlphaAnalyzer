🔥 ROOT CAUSE
─────────────
FMP Data Validator uses Promise.all() to validate 5 tickers concurrently,
causing bursts of 20 simultaneous API calls (5 tickers × 4 calls each).

This exceeds FMP's burst limits and triggers HTTP 429 errors.

The production-ready fmpRateLimitService (with token bucket + adaptive
backoff) exists but is NOT used by the validator.


📊 CURRENT IMPACT
─────────────────
▪ Severity: LOW (0.5% error rate)
▪ Reason: 80% cache hit rate masks the problem
▪ Affected: 1 stock (SO - Southern Company) cached as invalid
▪ Pattern: Isolated errors, not constant

⚠️  FUTURE RISK: HIGH after cache flush or with multiple workers!


🔍 EVIDENCE
───────────
1. Code (fmp-data-validator.ts:265):
   ```typescript
   const results = await Promise.all(
     chunk.map((ticker) => validateFMPData(ticker, true))
   );
   ```
   → Fires 20 concurrent API calls (5 × 4 endpoints)

2. Logs:
   "SO excluded: Request failed with status code 429"
   → Cached for 7 days to prevent retry storm

3. Math:
   ▪ Validator: 80 calls/sec (burst)
   ▪ FMP limit: 4 calls/sec (sustained)
   ▪ OVER LIMIT: 20× 🔴


✅ THE FIX (2 lines of code)
────────────────────────────
File: server/services/fmp-data-validator.ts:265

BEFORE:
  const results = await Promise.all(
    chunk.map((ticker) => validateFMPData(ticker, true))
  );

AFTER:
  const results = [];
  for (const ticker of chunk) {
    await fmpRateLimitService.acquireForCall(); // ← Add this
    const result = await validateFMPData(ticker, true);
    results.push(result);
  }

Impact:
  ✓ Burst: 20 calls → 1 call at a time
  ✓ Rate: 80/sec → 4/sec (compliant)
  ✓ 429 errors: eliminated
  ✓ Validation time: +4 seconds per batch (acceptable)
